3.2 Sökningen som inget gör

Symptom
Söker man på ett namn med apostrof, som O'Brien, på Monsters som frontdesk händer ingenting på skärmen.

Återskapa

1. Logga in som frontdesk och öppna Monsters.
2. Sök på ett namn som innehåller en apostrof.

Hypoteser

- Felet syns i webbläsaren. Test: Console. Resultat: bara "request failed" från apiFetch. Säger inte varför. Föll.
- Servern svarar med ett fel. Test: Network. Resultat: 500 och svaret "oops". Höll, men säger inte varför.
- Servern loggar orsaken. Test: terminalen där npm run dev kör. Resultat: ett SQL-syntaxfel som visar hela frågan med söktexten inklistrad. Höll.

Rotorsak
apps/api/src/legacy/monsters/monsters.routes.ts. Söktexten klistras in direkt i SQL-strängen i stället för att skickas som parameter. Apostrofen avslutar textsträngen i SQL, och frågan blir ogiltig.

Säkerhet
Det här är SQL injection: det användaren skriver blir en del av SQL-koden. Det ska hanteras som ett säkerhetsfel och rapporteras privat, som i 7.10. Hur det kan utnyttjas beskrivs inte här.

Åtgärd
Använd parametriserade frågor med ? och skicka söktexten separat, som legacy redan gör på andra ställen. Visa ett begripligt felmeddelande för användaren i stället för "oops". Kontroll: sökning på O'Brien fungerar, och ett test med en apostrof i söktexten.

Var hittade jag felmeddelandet? I terminalen. Console och Network sa bara att något gick fel, inte vad.
