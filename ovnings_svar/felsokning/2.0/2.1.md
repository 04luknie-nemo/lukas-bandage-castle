2.1 Labb: Datumet som flyttar sig

Symptom
Sir Snortlewicks vistelse visar hämtningsdatum 2026-11-24 i Stays-listan, men 2026-11-25 på vistelsens egen sida.

Återskapa

1. Kör npm run db:reset och starta appen med en server i en tidszon öster om UTC, till exempel svensk tid. I UTC syns inte felet.
2. Logga in som frontdesk och öppna Stays.
3. Jämför Pickup för Sir Snortlewick i listan med datumet på vistelsens sida.

Hypoteser

- API:t skickar olika värden. Test: Network. Resultat: listan, /api/stays, får expected_pickup "2026-11-24T23:00:00.000Z". Sidan, /api/stays/257/details, får expectedPickup "2026-11-25T00:00:00.000Z". Höll.
- Listan klipper bort klockslaget. Test: läste day() i StayListPage.tsx. Resultat: slice(0, 10) tar datumet i UTC. Höll.
- Skillnaden beror på serverns tidszon. Test: startade appen med TZ=UTC npm run dev. Resultat: båda visar 2026-11-25. Höll.

Rotorsak
Databasen har kolumnen som DATE, utan klockslag. Legacy, med mysql2, tolkar datumet som midnatt i serverns lokala tidszon. I svensk tid blir det 23:00 UTC dagen innan. Prisma tolkar samma datum som midnatt i UTC. Listan visar sedan bara de tio första tecknen med slice(0, 10), alltså datumet i UTC, och får dagen innan. Samma sak syns i checked_in_at, där listan får 11:15Z och sidan 12:15Z.

Åtgärd
Låt mysql2 läsa datum i UTC, eller skicka datum utan klockslag som text YYYY-MM-DD, som Del 3.7 i onboardingen beskriver. Kontroll: listan och sidan visar samma datum när servern kör i svensk tid.

Reflektion

Vilket steg gjorde störst skillnad?
Att starta appen med TZ=UTC. Det visade att felet beror på serverns tidszon och inte på datan.

Vilka andra datum kan ha samma problem, och hur hittar man dem?
Jag sökte med git grep -n "slice(0, 10)" -- apps/web/src och fick 24 träffar i 18 filer, men alla är inte fel. Om datumet kommer som midnatt i UTC, som från Prisma, blir slice rätt. Fel blir det om datumet kommer från legacy, där servern tolkar det i lokal tid, eller om dagens datum tas fram med new Date().toISOString().slice(0, 10), som ger datumet i UTC i stället för lokalt.
