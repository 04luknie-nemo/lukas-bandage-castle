4.1 Labb: Månaden som är fel

Symptom
Ticket #60 visar Created 31/09/2026 och Due 07/10/2026. 31 september finns inte. Datumen ligger en månad för tidigt, men dagen stämmer.

Återskapa

1. Kör npm run db:reset.
2. Logga in som keeper och öppna Tickets.
3. Titta på Created och Due för ticket #60.

Rotorsak
apps/web/src/utils/format.ts, rad 7, formatShortDate. getMonth() räknar månader från 0 i JavaScript, och funktionen lägger inte till 1. Infört av Tobias Fenwick 2023-06-21. Testerna kontrollerar formen dd/mm/yyyy och dagen, men aldrig månaden.

Åtgärd
Använd getMonth() + 1. Kontroll: ticket #60 visar 31/10/2026, och ett test som kontrollerar månaden, till exempel att 2026-11-04 blir 04/11/2026.

Reflektion
Vilken hypotes kunde jag fälla utan att köra något? Tidszonen. Symptomet var en hel månad med samma dag, och en tidszon flyttar högst en dag. Att titta noga på symptomet först sparade ett test.

Vad visar listan för ett datum i januari? Månaden blir 00, eftersom getMonth() ger 0 för januari.

Hur hade felet upptäckts tidigare? Med ett test som kontrollerar innehållet, inte bara formen, till exempel ett datum i januari som måste bli 01.

node -e "console.log(new Date('2026-01-15').getMonth())" i git bash ger 0, och inte 1
