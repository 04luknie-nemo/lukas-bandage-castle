5.4 Skiftbytet

Symptom
När Old Hobb tar Bryonys pass med Take it får han två pass på onsdag, 07:00–15:00 och 14:00–22:00. De överlappar mellan 14:00 och 15:00. När admin försöker lägga samma pass på Hobb nekas det.

Återskapa

1. Logga in som Old Hobb, öppna Rota och My shifts.
2. Ta Bryonys pass nästa onsdag med Take it. Det går.
3. Logga in som admin och försök lägga ett pass 14:00–22:00 på Hobb samma dag. Nekas med "Already working Wed 07:00–15:00" och "Only 9 hours rest between shifts (minimum 11)".

Hypoteser

- Bytet borde ha bytt Hobbs pass mot Bryonys. Test: läste acceptSwap. Resultat: Take it flyttar Bryonys pass till Hobb, och Hobbs eget pass ska ligga kvar. Det är tänkt. Föll.
- Reglerna saknas. Test: admin-formuläret. Resultat: admin nekas, så reglerna finns. Föll.
- De två vägarna kontrollerar olika saker. Test: Network och git grep "shiftProblems". Resultat: Take it går till POST /api/rota/swaps/1/accept och får 200. Admin går till POST /api/rota/shifts och får 409. shiftProblems används bara i rota.service.ts, inte i swaps.ts. Höll.

Rotorsak
apps/api/src/modules/rota/swaps.ts, acceptSwap. Funktionen flyttar passet till den nya ägaren utan att kontrollera reglerna. Admin-vägen i rota.service.ts anropar shiftProblems, som kontrollerar krockar, vila och max timmar i veckan. Take it-vägen gör det inte.

Åtgärd
Anropa shiftProblems i acceptSwap innan passet flyttas, och neka bytet om det finns problem. Kontroll: Take it nekas för Hobb med samma meddelande som admin får, och ett test för acceptSwap med ett pass som krockar.

Vilka antaganden visade sig vara fel?
Att Bryony skulle få Hobbs pass i utbyte. Att byta bort betyder att ge bort. Och att två pass samma dag var felet, när felet egentligen var att ingen kontroll gjordes.
