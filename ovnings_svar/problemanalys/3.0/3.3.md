## 3.3 Vad ska inte loggas?

### Symptom

Två av de 14 loggraderna i API:t skriver ut saker som inte borde hamna i en logg.

### Återskapa

git grep -n "console\." -- apps/api/src från 3.1, och läste varje rad.

### Rad 1: auth.service.ts rad 38

console.log(`🔑 Password reset for ${email}: ${config.webUrl}/reset-password?token=${token}`)

- Vem kan läsa: utvecklare, drift och alla med tillgång till loggverktyget.
- Vad kan hända: den som läser raden får token och kan byta lösenord på någon annans konto.
- I stället: logga bara att det hände och för vem, till exempel "Password reset requested for user 42". Token ska bara gå till användaren via e-post.

### Rad 2: ravenPost.ts rad 27

console.log('[raven] -> ' + r.email + ' (' + r.contact_pref + '): ' + r.subject)

- Vem kan läsa: utvecklare och drift kan se kundens e-post.
- Vad kan hända: personuppgifter riskerar att läckas eller synas för alla som har tillgång till loggverktyget. Ämnesraden kan också innehålla belopp.
- I stället: logga user id, till exempel "Raven post sent to customer 23".

### Rotorsak

Loggraderna skriver ut hela värden som e-post och token, i stället för id.

### Åtgärd

Byt e-post mot user id och ta bort token ur loggen.

### Verktyg

git grep för att hitta alla loggrader, och att läsa koden.
