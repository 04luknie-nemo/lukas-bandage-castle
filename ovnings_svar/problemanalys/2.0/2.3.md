## 2.3 Den saknade ticketen

### Symptom

När man trycker Load more på Tickets saknas en ticket vid varje sidbyte: 40 och 19. Samma fel som i Felsökning 2.2.

### Återskapa

1. Starta appen i JavaScript Debug Terminal och logga in som keeper.
2. Brytpunkt i listTickets i apps/api/src/modules/tickets/tickets.service.ts, efter raden där nextCursor räknas ut.
3. Öppna Tickets och tryck Load more.

### Hypoteser

- nextCursor pekar på den sista ticketen som visas. Test: Watch på items[query.take].id och items[query.take - 1].id. Resultat: första sidan 40 och 41, sista som visades var 41. Efter Load more 19 och 20. nextCursor blir 40 och 19, alltså den extra ticketen som aldrig visas. Föll.
- Nästa sida hoppar över cursor. Test: läste koden. Resultat: skip: 1 hoppar över ticketen som cursor pekar på, alltså 40 och 19. Höll.

### Rotorsak

tickets.service.ts, nextCursor: items[query.take].id. Koden hämtar 21 för att veta om det finns fler, men visar bara 20. nextCursor sätts till den 21:a, och skip: 1 hoppar över den på nästa sida.

### Åtgärd

nextCursor: items[query.take - 1].id, alltså den sista som visas: 41 och 20.

### Verktyg

- Brytpunkt i listTickets. Sidan laddar inte medan debuggern står still.
- Watch på items.length = 21, query.take = 20, items[query.take].id och items[query.take - 1].id. Värdena visade felet direkt, utan att räkna id:n på sidan.
- Call Stack ledde till tickets.routes.ts, ticketsRouter.get('/'), alltså GET /api/tickets.

### Frågor

Vilket id hade varit rätt? 41 på första sidan och 20 efter Load more, items[query.take - 1].id.
Vilken route anropade funktionen? GET /api/tickets i tickets.routes.ts.
