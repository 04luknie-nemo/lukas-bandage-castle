# 5.4 Labb: När något går fel

**Steg 2: hämtdatum före ankomstdatum**
Sidan stoppade mig innan något anrop gick iväg. Med curl i terminalen fick jag svaret {"error":"Validation failed","details":{"formErrors":[],"fieldErrors":{"endDate":["The pickup date must be after the arrival date"]}}}.

**Steg 3: var stoppades det?**
Regeln står på rad 18 i bookings.service.ts, som en .refine i zod-schemat. Schemat används av validate i routen, så anropet stoppades i validate innan servicen kördes. errorHandler gjorde om zod-felet till 400.

**Steg 4: statuskoder**

| Anrop                                                  | Statuskod                          |
| ------------------------------------------------------ | ---------------------------------- |
| /api/courier/jobs utan kaka                            | 401 Please log in                  |
| Samma med owners kaka                                  | 403 You are not allowed to do that |
| Samma med frontdesks kaka                              | 200 OK med kurirjobben             |
| POST /api/booking-requests/99999/approve som frontdesk | 404 Booking request not found      |

Första gången glömde jag bc_session= framför kakan. Då skickade curl ingen kaka, och jag fick 401 fast jag trodde att jag var inloggad.

**Hur visades felet för användaren?**
I webbläsaren stoppade sidan mig med ett meddelande innan anropet gick. Från API:t kom felet som JSON, så webben kan visa texten.
