# 3.3 Lager: route, service, databas

**Vilka routes hoppar över servicen?**
git grep -l "prisma\." -- 'apps/api/src/modules/_/_.routes.ts' gav 7 filer:

- courier/courier.owner.routes.ts
- monsters/monsters.routes.ts
- owners/owners.routes.ts
- search/search.routes.ts
- stays/extensions.routes.ts
- stays/stays.routes.ts
- visits/visits.routes.ts, med flest anrop: 11

**Jämförelse**
courier.owner.routes.ts kör med asyncHandler och prisma direkt i routen, samma med monsters.routes.ts. bookings.routes.ts använder metoder i bookings.service.ts, och det är servicen som hämtar från prisma.

**Är det alltid fel att routen pratar med databasen direkt?**
Det kan vara okej när routen bara läser data utan logik, till exempel en enkel lista. Men om samma anrop finns i flera routes, en get med ett anrop och en annan get med samma anrop plus ett eget, kan man missa något i koden. Har man en länk till bara en funktion finns logiken på ett ställe, och den hör till servicen.

**Vad blir svårare att testa?**
Ligger logiken i servicen blir det enklare att mocka och testa den. Ligger den i routen blir testerna beroende av HTTP och databasen.
